# p2p — 零基础设施的 UDP 打洞工具

**不需要任何服务器**，两端各跑一次，手工交换一行地址，就能在两台都在 NAT 后面的机器之间打通一条直连 UDP 通道。

```
A 机                                    B 机
  │  ./p2p advertise                      │
  │  → 223.104.79.59:27561                │
  │  ────── 人工把这一行发过去 ──────►      │
  │                        ./p2p connect 223.104.79.59:27561
  │◄══════════ UDP 直连通道 ═════════════►│
  │                                       │
  ✅ 双向验证通过，延迟 23ms              ✅
```

打通之后，如果还想**直接拿它跑 TCP**（比如把家里的远程桌面拉出来），加两个参数就行：

```
家里:  p2p advertise --share 3389
外面:  p2p connect 1.2.3.4:56789 --forward 13389:3389 --token <家里打印出来的密钥>
       # 然后 RDP 连 127.0.0.1:13389
```

数据面是 QUIC，**复用同一个已经打通的 socket**，所以不需要二次打洞。

---

## 为什么做这个

常见的 P2P 打通方案都需要一台公网服务器来做「信令」——两端先连到服务器上交换各自的公网地址。但如果你只是**偶尔**要在两台机器之间连一次，为了这个去租一台 VPS 实在不划算。

这个工具把「信令」这一步换成**人工**：你直接把 A 的地址复制粘贴给 B。反正就一次，复制粘贴比配一台服务器快多了。

**适合**：偶尔连一次的联机 / 远程访问 / 传文件
**不适合**：需要常年保持的通道（那还是自建 WireGuard + DDNS 更合适）

---

## 快速开始

1. 到 [Releases](../../releases) 下载对应平台的二进制，放到两台机器上

   > **Windows 用户可以直接双击 `p2p.exe`** —— 会弹出交互菜单，按提示选就行，不用记命令。

2. **A 机**运行：
   ```
   p2p advertise
   ```
   它会打印一行地址，比如 `223.104.79.59:27561`。**把这一行发给 B。**
3. **B 机**运行：
   ```
   p2p connect 223.104.79.59:27561
   ```
   它也会打印自己的一行地址。
4. **如果 20 秒内两端都显示 `✅ 通道建立成功`，就完事了。**

   如果 A 机提示「没有收到对方的任何数据包」，就**把 B 那行地址粘回 A**，回车即可。

> 第一次运行 Windows 会弹防火墙询问 —— 选**允许**。两端要用**同一个 `--port`**。

## 为什么有时候需要交换两次地址

这是本工具最容易被误解的地方，也是设计上的关键：

> **打洞的本质是：双方各自先向对方发一个包，在「各自的」NAT 上建立"允许对方回包"的规则。**

只建立一边的规则，另一边照样丢包。所以：

| 你的 NAT 类型 | 对方单向打过来能成功吗 |
|---|---|
| **全锥形（EIF）** | ✅ 能 —— 一步到位，不需要第二次交换 |
| 地址受限锥形 | ❌ 不能 —— 需要你也向对方发包 |
| 地址+端口受限锥形 | ❌ 不能 |
| **对称型** | ❌ 不能 —— 打洞基本无望 |

所以工具的策略是：**先只广播不催促**。对方能打进来就自动完成；打不进来再提示你粘贴对方地址，双向同时打洞。

`p2p probe` 会告诉你自己是哪一种。

## 命令

### `p2p probe` — 只探测 NAT 类型

```
$ p2p probe
  [OK] Google       -> 223.104.79.59:19265
  [OK] Cloudflare   -> 223.104.79.59:19503
  [OK] Nextcloud    -> 223.104.79.61:9909
  ...
  公网 IPv4       : 223.104.79.59, 223.104.79.61
  观察到的映射端口 : [9909 19265 19503 ...]
  NAT 类型: APDM (映射随目标变化 / 对称 NAT)
```

**打不通的时候，两端各跑一次 `probe` 对比结果**，基本立刻就能知道是谁的问题。

### `p2p advertise` — 广播模式

打印自己的公网地址，保持 NAT 映射存活，等待对方。

### `p2p connect <ip:port>` — 连接模式

拿着对方给的地址主动打洞。

### 通用选项

| 选项 | 默认 | 说明 |
|---|---|---|
| `--port N` | 45678 | 本地 UDP 端口，**两端必须一致** |
| `--timeout N` | 300 | 总超时（秒，也支持 `5m` 这种写法） |
| `--wait N` | 60 | 知道对方地址后，打洞尝试多久算失败（秒） |
| `--prompt N` | 20 | 多久没收到对方的包就提示粘贴地址（秒），仅 advertise |
| `--no-hold` | — | 成功后直接退出，不保持通道 |

### 数据面选项（可选）

| 选项 | 说明 |
|---|---|
| `--share P` | 开放本机 TCP 端口 P 给对方；`P=HOST:PORT` 可指向内网另一台机器；可重复 |
| `--forward L:R` | 本地监听 L，转发到**对方**的 R 端口；可重复 |
| `--token S` | 数据面共享密钥，两端必须一致；只在有 `--share` 的一侧可省略（自动生成） |
| `--bind ADDR` | `--forward` 的监听地址，默认 `127.0.0.1`（不对外暴露） |

退出码：`0` = 通道建立成功，`1` = 失败，`2` = 用法错误。

## 端口转发（数据面）

`--share` 和 `--forward` 配合使用，就能在打通的通道上直接跑 TCP。

**开放的一侧**（家里那台）：

```bash
p2p advertise --share 3389
```

它会打印两样东西，**都要发给对方**：

```
把这行发给对方：
      223.104.79.59:27561

数据面密钥也发过去：
      7f3a9c2e5b1d8046
```

- `--share 3389` = 对方可以访问我的 3389，实际连的是 `127.0.0.1:3389`
- 想开放内网另一台机器：`--share 3389=192.168.1.5:3389`
- 多条：`--share 3389,445` 或 `--share 3389 --share 445`
- **这是一份白名单**：没列出来的端口一律拒绝

**访问的一侧**（外面那台）：

```bash
p2p connect 223.104.79.59:27561 --forward 13389:3389 --token 7f3a9c2e5b1d8046
```

- 本地监听 `127.0.0.1:13389`，连上来的流量转发到**对方**的 3389
- 想给局域网其他设备用：`--bind 0.0.0.0`
- 多条：`--forward 13389:3389 --forward 13390:445`

然后 `mstsc /v:127.0.0.1:13389` 就能连上家里的远程桌面。

### 关于 `--token`

**它不是一个可有可无的装饰。** 打洞打出来的是一条**裸的** UDP 路径，
任何知道你这一轮公网 IP:端口的人都能往上面发 QUIC 握手包。`--token` 是
这条路径上**唯一**的身份校验：

- 两端用同一个 token，各自用 HKDF 派生出一对 ed25519 密钥
- 服务端出示 server 证书、并要求对方出示证书；客户端只认 server 公钥
- token 不一致 → 握手直接失败，一个字节都过不去

不需要 CA，不需要交换证书指纹，token 可以像地址一样靠聊天工具发过去。
只在有 `--share` 的那一侧可以省略（会自动生成并打印）。

> ⚠️ 别图省事把 token 设成 `123456` 这种。**它就是你的门锁。**

### 性能

数据面用 QUIC，**有正经的拥塞控制和丢包恢复**。这不是过度设计：
在 UDP 上粗糙地隧道 TCP 会踩经典陷阱——外层丢包被内层 TCP 误判成拥塞，
两端窗口一起塌陷，吞吐断崖式下跌。

回环实测（只代表协议栈本身的上限，实际受限于链路）：
1 MB 数据往返 **12.1 MB/s**，8 条并发连接正常。

真实链路上的瓶颈永远是链路本身：走手机热点时裸带宽只有 2.4~3.8 Mbps，
打洞打得再直也快不过这个数。

## 打不通怎么办

工具失败时会明确告诉你**收到了几个包**，这比笼统的"连接失败"有用得多：

| 现象 | 含义 |
|---|---|
| 两端都收到 0 个包 | 包根本没到对端 —— 大概率有一端是**对称 NAT** 或 CGNAT |
| 一端收到、一端 0 个 | 单向能通、反向不通 —— 典型的不对称 NAT 组合 |
| 都收到了但没握手成功 | 有意思，请提 issue 附上两端的 `probe` 输出 |

**最常见的原因，按可能性排序：**

1. 任一端是**对称 NAT**（跑 `p2p probe` 看）
2. 任一端在运营商 **CGNAT** 后面且端口随机化（国内移动/联通宽带很常见）
3. **本机防火墙**拦了入站 UDP（第一次运行要在弹窗里选「允许」）
4. 两端在**同一个 CGNAT** 内，而该 CGNAT 不支持回环（hairpinning）
5. 公司/校园网**封了 UDP**

> 💡 **先检查一件事**：如果两端都有**公网 IPv6**，直接用 IPv6 连会比打洞简单可靠得多——IPv6 没有 NAT，`probe` 会告诉你有没有。

## 已知限制（刻意的设计取舍）

- ❌ **不提供中继兜底**。打不通就是打不通，直接报错。想要"一定能连上"就得上带中继的方案（自建 VPS + frp/wireguard）。
- ❌ **只支持 IPv4**。IPv6 不需要打洞。
- ❌ **不是常驻服务**。没有保活/自启设计，跑完就退出。
- ⚠️ **纯打洞模式（不加 `--share` / `--forward`）的通道不加密**——那只是一个建链工具，
  要在上面跑敏感流量请自己套 WireGuard。加了数据面之后走 TLS 1.3 且两端互相认证，是加密的。
- ⚠️ **数据面引入了 `quic-go` 依赖**（纯打洞模式其实用不到，但同一个二进制里链进去了）。
  探测/打洞逻辑本身仍然是纯标准库。

## 它是怎么工作的

1. **探测**：用同一个 UDP socket 向 7 个不同 AS 的 STUN 服务器查询。如果所有目标看到同一个映射端口 → EIM；端口随目标变化 → 对称 NAT。
   - ⚠️ 必须复用同一个 socket。每问一个目标就新建 socket 的话，源端口变了，映射端口当然不同，**结论必然是错的**。
2. **保活**：NAT 映射 30 秒~5 分钟就会过期，而人工传递地址要花时间。所以拿到对方地址前，每秒 15 秒向"给出这个映射的那台 STUN 服务器"发一个包，把映射撑住。
3. **打洞**：双方各自以 200ms 间隔持续向对方发包。
4. **验证**：不是"收到包就算成功"——收到只证明**对方→我**通了。协议里带 ping/pong，**双方都收到过 pong** 才算通道建立。这样"单向通"的假成功会被识破。
5. **数据面**（可选）：QUIC **复用同一个已经打通的 socket**——另开 socket 会拿到一个没被打通的 NAT 映射，等于白打一次洞。
   - 我们的包和 QUIC 包靠首字节区分：魔数 `*P2P` 的首字节是 `0x2A`，bit7/bit6 都为 0，
     而任何 QUIC 包头必然带 `0x40` 或 `0x80`，所以分类是**确定性的**，不会误判。
   - 复用方式是用 quic-go 的 `Transport.ReadNonQUICPacket` 把非 QUIC 包取回来，
     这样能把原始 `*net.UDPConn` 整个交出去，保留 DF 位（DPLPMTUD 的前提）、ECN 和 GSO/GRO。

探测/打洞部分零第三方依赖，纯 Go 标准库；数据面用到 `quic-go`。

## 自己编译

需要 **Go 1.23 或更高**（数据面依赖 `quic-go` v0.54）。

```bash
git clone https://github.com/HongY1Ng/p2p-ipv4
cd p2p-ipv4
go mod download        # 需要能访问模块代理；国内建议 export GOPROXY=https://goproxy.cn
go build -o p2p .      # Windows 下是 go build -o p2p.exe .
```

跑测试：

```bash
go test ./...
```

交叉编译（一次出 6 个平台，产物在 `dist/`）：

```bash
go run build.go
```

或者手动指定：

```bash
GOOS=windows GOARCH=amd64 go build -o p2p_windows_amd64.exe .
GOOS=linux   GOARCH=amd64 go build -o p2p_linux_amd64 .
GOOS=darwin  GOARCH=arm64 go build -o p2p_darwin_arm64 .
```
