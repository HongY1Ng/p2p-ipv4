# 从 IPv6 项目复用的经验（避坑清单）

这些都是刚做完家里那套 IPv6 方案时真实踩过的坑，本项目可以少走一遍。

---

## 1. ⚠️ PowerShell 的位移运算会按 byte 类型截断

**这是写本项目 NAT 探测器时踩到的新坑，非常隐蔽。**

```powershell
$data = @([byte]0x01, [byte]0x01)     # STUN 响应前两字节
$mtype = ($data[0] -shl 8) -bor $data[1]
# 期望 0x0101  = 257
# 实际 0x0001  = 1     ← 因为 [byte]1 -shl 8 在 byte 内截断成了 0
```

**后果**：所有 STUN 响应都被判定为"类型不对"而丢弃 → 全部显示"无响应" → 误判成"出站 UDP 被封"。**排查花了不少时间。**

**规则**：解析二进制协议时，**每次移位前都显式转 `[int]`**：

```powershell
$mtype = ([int]$data[0] -shl 8) -bor [int]$data[1]
```

C#/Python 不会这样（它们会提升到 int），**只有 PowerShell 有这个坑**。

## 2. NAT 探测必须复用同一个 socket

判断"映射是否随目标变化"（EIM vs 对称 NAT）时，**必须用同一个 UDP socket、同一个内网源端口**去问多个不同的公网目标。

如果每问一个目标就新建一个 socket，源端口就变了，看到的映射端口当然不同——**结论必然错成"对称 NAT"**。

（这个错误我们犯过一次，结果把好的网络误判成对称 NAT，白白绕了一大圈。）

## 3. PowerShell 脚本里的中文必须存成 UTF-8 **with BOM**

Windows PowerShell 5.1 对**无 BOM** 的 UTF-8 文件按 GBK 解码，中文会变成乱码，然后报一堆莫名其妙的语法错误（`Unexpected token`）。

写入方法：
```powershell
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($true)))
#                                                                        ↑ $true = 加 BOM
```

**用记事本保存是陷阱**——新版记事本默认存 UTF-8 **不带** BOM。

## 4. 看防火墙状态必须看 `ActiveStore`

```powershell
# ❌ 默认读的是 PersistentStore（配置文件里存的，可能和实际不符）
Get-NetFirewallProfile | Select-Object Name, Enabled

# ✅ 必须明确指定 ActiveStore（真正生效的）
Get-NetFirewallProfile -PolicyStore ActiveStore | Select-Object Name, Enabled, DefaultInboundAction
```

我们遇到过 **PersistentStore 显示 `True`、ActiveStore 显示 `False`** 的情况——防火墙实际是关的，所有规则形同虚设，但常规排查完全看不出来。

## 5. 注册表里有"非标准"的防火墙禁用策略键

```
HKLM\SOFTWARE\Policies\Microsoft\WindowsFirewall\
    DomainProfile      ← 标准
    StandardProfile    ← 标准（对应"专用"配置文件）
    PublicProfile      ← 标准
    PrivateProfile     ← ⚠️ 非标准！但会被生效
```

只要里面有 `EnableFirewall = 0`，对应配置文件就被**静默关闭**，`netsh advfirewall set ... state on` 也会被压回去。

**排查清单**：
- 先删这些策略键
- `gpupdate /force`
- `netsh advfirewall set allprofiles state on`
- 再复查 `ActiveStore`

## 6. Windows 上装 WireGuard 服务用命令行，别用 GUI

```powershell
# 装成 Windows 服务（开机自启，可脚本化管理）
& 'C:\Program Files\WireGuard\wireguard.exe' /installtunnelservice "C:\path\to\wg.conf"
sc.exe config 'WireGuardTunnel$隧道名' start= auto

# 卸载
& 'C:\Program Files\WireGuard\wireguard.exe' /uninstalltunnelservice 隧道名
```

**注意**：这样装的隧道**不会出现在 WireGuard GUI 的列表里**（GUI 只管理它自己 `Data\Configurations` 下的加密配置）——这是正常的，不是出问题。

改配置后要「卸载 + 重装」才能生效。

## 7. WireGuard 的 `Endpoint` 可以直接写域名

WireGuard **每 120 秒重新解析一次** `Endpoint` 的主机名。所以配合 DDNS，家里地址变了隧道能自动跟上，**不需要额外写同步脚本**。

## 8. 端到端验证要用第三方外部视角

不要只信自己的探测。用 **Globalping**（`api.globalping.io`，免费公开 API）从全球多个节点验证：

```powershell
# TCP 端口探测
$b = @{ type='ping'; target='<IPv6地址>'; limit=4;
        measurementOptions=@{ packets=2; protocol='TCP'; port=3389 } } | ConvertTo-Json -Depth 5
$m = Invoke-RestMethod -Uri 'https://api.globalping.io/v1/measurements' -Method Post -Body $b `
        -Headers @{'Content-Type'='application/json'} -TimeoutSec 30
# 然后轮询 /v1/measurements/<id> 直到 status = finished
```

**必须带对照组**（探测一个确定没有服务的端口，确认它返回"无应答"）——否则无法区分"真通"和"探测工具骗你"。我们就因为缺少对照组，一度把 `status=finished`（测量跑完）误读成"探测成功"。

## 9. DNS 污染要识别清楚

某些域名（如 `download.wireguard.com`）**只是 DNS 被污染，IP 层可达**：

```powershell
# 系统 DNS 返回污染地址
Resolve-DnsName download.wireguard.com -Type A
# 用 DoH 查真实 IP（腾讯 doh.pub / DNSPod 较准，阿里 DoH 有时也给错）
curl.exe -s -H "accept: application/dns-json" "https://doh.pub/dns-query?name=download.wireguard.com&type=A"
# 然后用真实 IP 直连（保持 Host 头/SNI 正确）
curl.exe -L --resolve download.wireguard.com:443:<真实IP> -o out.exe https://download.wireguard.com/...
```

**走真实 IP 时务必校验数字签名**（这是唯一的安全保证）。

## 10. 国内做 DDNS 的实际选择

| 服务 | 结论 |
|---|---|
| **dynv6.com** | ❌ 账号激活页用 Google reCAPTCHA，国内加载不出来，永远激活不了 |
| **公网 IP 探测** | 别用系统 DNS，用 DoH |
| **腾讯云 DNSPod** | ✅ 国内最稳，支持 AAAA；但 `DescribeRecordList` 查不到记录时是**抛异常**（`NoDataOfRecord`）而不是返回空列表，代码要处理 |
| **小米路由器自带 DDNS** | ❌ 只支持 A 记录且上报的是 WAN IPv4（CGNAT 环境下没用） |
| **ntfy.sh** | ✅ 免费、免注册、纯 HTTP、国内可直连——**不适合做实时信令，但非常适合做"地址发布"** |
| **broker.emqx.io** | ✅ 公共 MQTT broker，国内厂商，实测可直连——**适合做实时信令** |
